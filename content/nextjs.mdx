Next.js adds routing, rendering, and server-side app capabilities to React. A description of what the framework does is one thing. An explanation of what a specific version changes is another.

The App Router and Server Components were built into Next.js before version 15. Calling them new in version 15 makes it difficult to understand what an upgrade accomplishes.

## The changes to notice

The [Next.js 15 release announcement](https://nextjs.org/blog/next-15) highlights asynchronous request APIs, changed caching defaults, and stable Turbopack support for development.

Request-dependent APIs such as `cookies`, `headers`, and route parameters moved toward asynchronous access. For example, a version-15 App Router page reads its parameters like this:

```tsx
export default async function Post({
  params,
}: {
  params: Promise<{ slug: string }>;
}) {
  const { slug } = await params;
  return <h1>{slug}</h1>;
}
```

This example is specifically for Next.js 15. It is not a statement that older projects already use the same parameter type.

Caching also became something to inspect carefully: `fetch` and ordinary `GET` route handlers are not cached by default in the same way as earlier App Router defaults. Client page segments changed too, while shared layouts and back/forward navigation retained distinct caching behaviour. Treating every cache as one mechanism is a source of confusion.

## Follow one request through the application

For learning, I would start with one route and ask where each operation happens. Which component reads the data? Does the result depend on this request? What is sent to the browser? What should remain fresh on the next visit?

Those questions make the abstractions easier to reason about than a long list of framework features. A page that appears correct on the first load can still behave unexpectedly after navigation or a data update.

## The second visit matters

My first upgrade question would be what changes on the second visit. The initial page load can look right while navigation or cached data behaves differently. I would follow one changing piece of data through a reload, a client navigation, and a return visit before deciding that the upgrade preserved the behaviour I wanted.
